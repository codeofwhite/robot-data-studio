# 自然语言布料专家 Agent：执行计划与开发日志

状态：计划文档已批准；功能实现尚未批准。

创建日期：2026-10-12。

## 1. 目标与范围

用户在一个通用布料工位中用自然语言描述目标，系统理解目标、观察当前衣物、组合动作能力、执行并根据形变调整下一步，最终保存轨迹、视频、Episode 和决策过程。

任务不要求逐个预先编写完整脚本。机器人动作能力、状态表示和可组合的评估条件需要预先实现；超出能力范围的任务应明确说明缺少什么能力。

示例指令：

- “把桌沿的毛巾取回来，铺到桌子中央。”
- “把布移到右侧，保持朝向不变。”
- 后续扩展：“把上衣袖子向内折，再对折。”

首版候选范围为矩形布／毛巾，支持取回、移动、旋转对齐和铺开。折叠、复杂衣物、双臂协调和不同物理后端随后分阶段增加。以上是路线规划，不是全部功能的实现授权。

## 2. 已有基础与未完成能力

当前任务中心可查看历史操作成果、失败原因、视频和 Episode，并导入已交付示范。任务复跑入口尚未开放。

已有 `tabletop_v2` 桌面任务包含 cuRobo 规划、局部辅助夹持、拉动、释放、重新读取布角位置、阶段记录与任务指标。该批次采用 Genesis 单臂物理执行和 Isaac 状态回放渲染；不能据此宣称截图中的双臂工位已支持自然语言任务执行。

已有衣物外观批量流程可对记录状态重新渲染。自然语言专家生成还需要方案解释器、任务运行编排、模型接入和反馈迭代，不能仅复用重渲染来声称产生了新动作轨迹。

## 3. 系统流程与职责

```text
自然语言指令 + 当前场景
    → 目标解析与任务定义
    → 衣物状态／语义结构／候选操作点
    → DeepSeek 选择策略与下一动作
    → 执行层解析参数 → cuRobo 规划 → 仿真执行
    → 重新观察 → 固定评估器判断进展
    → 继续、生成修正方案或结束
    → 保存轨迹、视频、Episode 和可追溯记录
```

| 模块 | 职责与边界 |
| --- | --- |
| 目标解析 | 将自然语言变成结构化目标和条件；遇到“整齐”等歧义，显示理解结果供用户修改／确认。 |
| 场景能力描述 | 提供机器人、工作范围、衣物类别、可用动作和当前状态；不承诺不存在的动作能力。 |
| 衣物结构表示 | 提供布角、边界及后续袖口／裤脚等语义部位；第一版可来自仿真完整状态。 |
| DeepSeek | 组合已有能力，决定动作顺序、操作对象和参数；不能自行改评估阈值或直接宣布任务成功。 |
| 动作执行层 | 在执行前解析当前语义点位置，调用接近、抓取、抬升、拉动、放置和释放等原语。 |
| cuRobo | 计算机器人运动；规划成功不代表衣物抓取、形变或任务成功。 |
| 仿真 | 推进机器人和布料状态，记录实际施加的动作与结果。 |
| 评估器 | 根据冻结的任务条件判断阶段进展和最终结果；任务成功、物理有效性、交付完整性和训练 QA 分开记录。 |
| Studio | 编辑方案、编排运行、显示进度与结果，管理版本和证据入口。 |

## 4. 任务定义与成功条件

任务定义需要保存原始指令、解析目标、初态要求、允许动作、终止条件、评价方式和版本。目标由通用条件组合；不把自然语言入口实现成只匹配已有脚本名称的按钮。

| 目标 | 候选条件 | 实施时需确认 |
| --- | --- | --- |
| 取回桌面 | 桌外／悬挂部分比例，桌面承载状态 | 桌面范围、比例计算方法和容差。 |
| 移到指定区域 | 中心或指定部位进入目标区域 | 用户指代的是整件衣物、中心还是局部。 |
| 保持朝向／旋转对齐 | 初始或目标方向误差 | 朝向参考与衣物对称性。 |
| 铺开 | 投影覆盖、折叠状态、语义部位展开 | 参考形状、面积度量和局部重叠检查。 |
| 后续折叠 | 折线、部位对应、目标形状和层叠关系 | 单看投影面积不足以判断正确折叠。 |

阈值在实施前结合当前指标、实际样例和人工回看确定并版本化。评价定义改变时单独升版本；旧结果保留原标准，重新评价产生新结果记录。

现有 `tabletop_v2/metrics.py` 使用规则网格四角和投影凸包面积，适合当前矩形布的粗略诊断。扩展到 T 恤／裤子时，凸包会计入部位之间空白，四角编号也不能直接复用；届时需评估投影三角形并集／掩码和语义关键点方法。

## 5. 执行阶段与验收

### A：通用执行能力与运行入口

梳理已有动作，提供结构化动作解释器、场景能力描述和运行接口。用现有成功配方作为参考方案；语义操作点在执行前重新定位。先以矩形布和已验证执行环境减少额外适配。

验收：从 UI 执行一份显式方案，看到阶段进度、停止入口、实际轨迹、评估和回放；已有示范及原始产物不覆盖。单臂辅助夹持作为首个适配器候选，是否首版就接双臂须在实现前确定。

### B：自然语言生成目标与方案

接入后端 DeepSeek 客户端，先解析目标，再根据状态与能力生成结构化方案。UI 显示系统理解、动作步骤和可编辑参数，支持保存新版本。

验收：在同一个场景中使用取回、移动、对齐等不同指令，得到不同目标与动作，并实际执行；任务不限于一条固定脚本。对当前能力不支持的目标明确报告缺口。

### C：反馈迭代与版本比较

执行后汇总阶段、抓取结果、目标误差、前后变化和规划失败原因。用户点击“根据结果优化”生成新方案，展示修改差异。后续增加有限轮自动迭代，保留失败并明确停止原因。

验收：一条“失败 → 反馈 → 新版本 → 再运行”链可完整回溯；模型不能修改冻结的成功标准。用相同初态／Seed 对比方案，再以未参与修改的初态评估。

### D：批量生成与数据交付

固定方案版本，采样初始位置、朝向等已支持条件；执行前根据当前形状适配动作。改变初态或物理参数需要重新执行仿真。纯材质／相机／灯光变化可复用成功轨迹重渲染，明确标为视觉衍生结果。

验收：批次逐条记录结果、失败类型、动作次数和成本，关联视频与 Episode。成功专家示范必须通过既定任务评估；交付与训练 QA 保留独立状态。

各阶段实施前进行只读检查，列出精确代码文件、接口、目标环境和验证命令，再单独申请批准。

## 6. 可追溯数据设计

任务版本、方案版本、运行记录和评价版本各自有独立标识。建议运行产物根目录为 `data/expert_agent/`，仅为路径规划，本次不创建该目录。

| 记录 | 最小内容 |
| --- | --- |
| 任务版本 | 原始指令、解析目标、能力要求、成功／终止条件、评价器版本。 |
| 方案版本 | 父版本、来源（参考／人工／模型）、完整步骤、参数、修改原因、触发反馈、内容哈希。 |
| 模型调用 | 模型名称、提示词版本、请求／响应、关联状态快照、时间与实际返回的用量；不保存密钥。 |
| 运行 | 任务与方案版本、代码提交号及实际执行代码哈希、Seed、资产／场景／物理版本、环境信息、请求与实际动作、阶段事件。 |
| 评价 | 初态有效性、阶段与最终条件、物理指标、失败原因、评估版本；不只保存成功布尔值。 |
| 交付 | 轨迹、视频、Episode 标识、关键产物哈希，以及物理执行和状态回放渲染的来源关系。 |
| 数据边界 | 辅助夹持标记；仿真完整状态专家信息与策略相机观测分开保存，避免训练输入误用。 |

方案修改创建新版本，不覆盖父版本；每次执行创建独立运行。进行中的状态可更新，完成后的证据保留。后续重渲染或重新评价关联原运行，不能冒充重新执行或替换原评价。

## 7. Token 与迭代成本

模型负责目标解析、初始策略和必要的阶段修正，不逐仿真步调用。正常动作执行、坐标更新和指标计算由程序完成。

只发送任务相关结构、候选操作点、指标和简短历史；不发送完整大网格或无界日志。先采用结构化状态反馈；图像反馈依实际模型能力和需求单独设计。

记录每次实际返回的输入／输出及供应商提供的其他用量字段；无法获得的字段标未知，不填虚构用量。批量执行复用固定策略，同时重新计算动作，不盲目回放旧坐标。

可配置模型调用次数、自动迭代轮数和 Token 预算，显示累计用量及停止原因。预算主要用于限制后续调用，不能保证正在进行的调用恰好停止在某个 Token 总数。费用估算需记录模型价格来源和日期。

## 8. UI 方案

复用布料任务中心，增加专家生成入口，保持紧凑折叠结构：

- 任务层：原始指令、解析目标、最近结果。
- 方案层：版本、父版本、修改摘要，展开后编辑步骤。
- 运行层：Seed、阶段、评估状态，展开后看视频、失败原因和 Episode。
- 模型请求、详细参数、日志及指标默认折叠。

核心操作为生成方案、保存新版本、运行、停止、根据反馈优化、比较版本和启动批次。实现阶段需明确运行停止、渲染、入库分别对应的状态。

## 10. 验证策略与待决策项

每阶段先做最小正常使用链路，不新增与实现重复的防御性测试矩阵。必要检查覆盖结构化方案能否执行、结果是否可信、证据是否完整、UI 是否可用。Python 语法／相关类型检查／前端构建按实际修改范围执行。

优化记录比较任务成功、动作次数、耗时、失败分类及 Token；一次成功不等于稳定提升，旧示范成功也不自动赋予新运行成功标签。

实施前待确认：

1. 首个执行适配器采用已有单臂辅助夹持，还是直接开发双臂；统一的工位概念不等于两者接口已相同。
2. 矩形布资产、场景范围、坐标系、原语参数及任务条件的精确定义。
3. DeepSeek 的实际端点、模型、可用输入格式和用量字段；密钥只放后端配置。
4. GPU、运行环境、进程停止与重启后的任务状态处理。
5. 首次验收的具体指令、初态、Seed、证据保存位置及对比方法。

### 2026-10-13：Newton 双臂工位故障与修复

本节是随后单独批准的工位修复记录；上段“本次”限制指 2026-10-12 的文档创建。自然语言 Agent 功能仍未实现。

**直接证据**：用户 Newton 会话 `20261013T120828+0800_bimanual_tabletop_v17_clothforge_keyboard_db59b60e` 显示双臂只剩底座。GPU 4 独立复现中，首步关节达到数百至数千弧度，随后双臂状态为 NaN；原生物理位置、控制接口和 Fabric 变换一致，故障属于物理发散，不能归为 WebRTC 丢帧。

**定位结果**：

1. 重置只写当前关节／粒子状态，连杆 FK 与上一状态未一起同步。双向耦合通过相邻状态计算接触速度，旧直立姿态产生虚假高速接触。首步传给刚体求解器的最大力／力矩分量约 `2.1568e8`；同步两个状态后该首步值约为 `661.8`，但单独这一改动仍不足以完成修复。
2. ClothForge 独立 Newton 1.4 的接触阻尼为绝对系数：`damping_hessian = kd / dt`。Isaac 当前捆绑 Newton 的实现为 `damping_hessian = ke * kd / dt`。直接复制 `ke=10000、kd=10` 会将等效阻尼放大 10000 倍。适配后 solver `kd=0.001`，保持绝对阻尼 `10 N·s/m`，没有降低源资产的物理阻尼。
3. 工位硬编码单个子步，没有采用衣物配置的 8 子步；改为读取该积分配置。双臂约束容量原为 `njmax=40`，日志要求至少 74；衣物工位改用 `512` 行约束和 `128` 个接触容量。

初始化修正、容量增加、关闭 CUDA 图或单独增加子步均不能独立证明故障已解决。最终组合验证保留 CUDA 图及双向耦合；没有改摩擦、材料刚度、成功阈值或安全限制。cubric 版本警告仍存在，本次没有证据将它认定为消失故障根因。
