# GarmentCodeData 导入执行计划

更新日期：2026-10-12。关联任务：G007。状态：阶段 1 已验证，首个批次包完整下载，12 件样本格式检查完成；转换代码、UI 与运行尚未批准。

## 目标与范围

将 GarmentCodeData v2 纳入 Studio 的外部衣物目录，支持分类检索、三维预览、材质选择，以及把选定样本转换为可在现有工位和 Newton 批量流程中使用的资产。

执行顺序为：样本与格式确认 → 少量转换及正常运行 → 导入 UI → 全量索引与批次转换 → 参数化编辑。先保证少量衣物能走完现有链路，再扩大目录规模。现有 ClothForge 基础库与 G003–G006 自定义款式继续使用。

“全量接入”首先指所有已取得样本可索引、检索；不要求首次扫描就完成全部几何转换、缩略图生成、资产注册和物理运行。这几个步骤分别记录进度。

| 能力 | 用户能做什么 | 所需数据／处理 |
| --- | --- | --- |
| 可浏览 | 找衣物、查看来源及样本变体 | 目录索引、类别映射、预览几何或图片 |
| 可模拟 | 选择物理材料，悬挂／落布，带入工位 | 统一单位与坐标、模拟网格、静止形状、缝合对应和运行配置 |
| 可调参 | 改衣长、领型等后重新生成 | 原始设计参数、人体测量及兼容的 GarmentCode 生成程序 |

导入成功不自动证明机器人任务成功；现成网格也不自动获得连续调参能力。

## 已确认依据与待确认项

官方项目描述约 115,000 个数据点，覆盖上衣、裙子、裤子、连衣裙、连体服等，并包含不同人体形状和三种纺织材料。数据点数不能直接当成独立款式数。[官方项目页](https://igl.ethz.ch/projects/GarmentCodeData/)

v2 的官方发布记录日期为 2024-09-04，列出的许可为 CC BY 4.0。导入记录应保留作者、版本、来源与许可；代码库的 MIT 许可与数据许可分别记录。[v2 发布记录](https://www.research-collection.ethz.ch/items/9d16a4da-0d30-4963-8842-af20fcf82899)

本地 GarmentCode 固定提交为 `d449629979028123a5c4dc9e732a2ec19b7fce31`。可复用组件与单位说明见 [能力清单](GARMENTCODE_CAPABILITIES.md)，实际已完成工作见 [衣物演进记录](CLOTHING_EVOLUTION.md)。

阶段 1 已找到可用的官方共享入口，并提取检查 12 件实际样本。格式与证据见 [阶段 1 格式核对](GARMENTCODEDATA_FORMAT.md)。发布元数据标注全量约 368 GB；本次批准只取第一批次中性人体压缩包 5,121,727,032 字节及配套文件，保留压缩包，仅解压 12 件。

已确认：衣物为二进制 PLY，含 UV；版片为 JSON，人体／设计参数为 YAML；衣物厘米制、Y-up，中性人体 OBJ 米制。PLY 为 UV 拆点，而原始静止边长、分区与标签使用原模拟编号。静止边长字典仅覆盖缝合附近；不能直接拼成当前模拟输入。

后续仍需确定：原模拟拓扑／静止度量如何恢复、视觉与模拟编号映射、复杂衣物初始姿态及挂点、材料参数适配、实际转换与运行开销。没有下载配对随机人体或全量数据，也没有注册或运行这些样本。

## 目录与元数据约定

建议数据根目录独立于 Git 仓库，具体位置在阶段 1 批准时确定：

```text
GarmentCodeData/
├─ raw/v2/                 原始发布数据，导入器只读
├─ catalog/                目录索引、类别映射和扫描报告
├─ converted/              已转换的衣物及转换版本
└─ jobs/                   导入计划、进度、结果和失败原因
```

Studio 注册记录引用转换产物，并保留原始来源引用。已有 `data/cloth_runs/` 等运行结果目录继续按现有配置使用；不在这份计划中另建 Episode 格式。

目录索引拟记录：数据集版本、原始样本 ID、设计 ID、人体／材料变体、原始类别、映射类别、原始文件位置、可用能力、转换版本和产物位置。字段能否直接取自上游需阶段 1 确认；没有可靠设计关系时不按文件名臆造分组。

稳定身份由数据集版本与上游样本 ID 确定，转换版本另行记录。一次完整、可用的转换才注册相应模型与配置。原始参数、上游物理材料与本地运行参数分别保留，后续录制仍走现有 Episode 流程。

## 阶段 1：取得少量样本，确认格式

**状态**：已验证；6 个下载文件字节数核对通过并记录 SHA256，12 件样本格式检查完成。详细记录见 [GARMENTCODEDATA_FORMAT.md](GARMENTCODEDATA_FORMAT.md)。

**输入**：官方 v2 发布说明、下载清单及少量样本。若已有本地数据，优先只读检查已有目录。

**操作步骤**：

1. 找到可用的官方下载入口，记录包大小、内容范围和许可；决定先取哪个最小可用包。
2. 核对磁盘空间，确定原始目录、转换目录以及目标 Python 环境。
3. 批准具体下载／解压命令后，取得样本并保存原始目录清单。
4. 对照上游代码，追踪一个样本的设计参数 → 版片／缝合 → 网格与静止信息。
5. 从实际可用样本中选约 12 件：上衣、裤子、裙子为主，包含少量复杂结构，形成固定试导入清单。

**产物**：格式说明、下载与空间记录、样本清单、字段映射表、一个样本的对应关系证据。

**拟涉及模块**：上游文档与数据读取；尚不修改 Studio UI。

**完成标准**：能准确指出每项模拟输入从哪里获取；明确哪些样本可直接转换、哪些需要重新生成或网格化。确实缺少静止信息的样本可先浏览，但不标为可模拟。

## 阶段 2：打通少量转换与正常使用

**输入**：阶段 1 固定样本清单与确认后的字段映射。

**操作步骤**：

1. 实现读取与转换：统一米制、坐标轴，保留初始位置与版片静止信息；处理缝合和顶点对应。
2. 输出现有流程所需的模拟网格、来源 manifest、预览几何、UV 与配置。拟沿用 `mesh.npz`、`manifest.json` 等本地约定，实际适配方案在样本核对后确定。
3. 将转换资产注册到独立数据源；保留原始样本与转换版本，不覆盖基础库。
4. 选上衣、裤子、裙子各一件，走预览 → 换材质 → 保存 → 工位配置跳转，并各运行一次已有两秒 Newton 悬挂流程。
5. 对固定试导入批次记录转换结果与具体失败原因；复杂结构不直接沿用简单双片衣物的成功结论。

**产物**：转换工具、试导入报告、已注册模型／配置、浏览器证据和 Newton 运行结果。

**拟涉及模块**：ClothForge 外部数据转换；Studio 来源配置、导入服务、衣物预览及运行来源支持。

**完成标准**：三种代表类别可实际预览、应用 PBR、保存、带入工位配置并正常完成 Newton 短轨迹；静止形状与缝合来源明确。此阶段不要求启动机器人任务。

## 阶段 3：接入外部资产导入 UI

**输入**：可工作的目录扫描／转换服务，以及阶段 2 的正常流程。

建议路由为 `/assets/import`，入口为“资产与材料 → 外部资产导入”。第一版选择 GarmentCodeData 和服务器本地目录；数据下载使用官方渠道或服务器命令行，不做浏览器上传整个数据集。该路由及接口名称均为建议，尚未实现。

| 默认折叠区域 | 操作与信息 |
| --- | --- |
| 数据源 | 数据集与本地目录、版本、许可、扫描进度、样本统计 |
| 样本选择 | 类别／设计属性筛选、分页缩略图；展开查看人体与材料变体 |
| 导入任务 | 查看计划、启动、进度、成功／失败数量、具体原因、继续未完成项 |

**操作步骤**：

1. 页面请求后端扫描结果和分页样本，不把全量网格一次送入浏览器。
2. 选择样本后先显示计划：哪些需转换、哪些已存在、预计输出位置和任务数量。
3. 启动后显示扫描、转换、注册的独立进度；保存结果可跨刷新恢复显示。
4. 单项失败记录样本 ID、阶段与原因，继续其他独立样本；用户显式选择重试，不自动换参数冒充成功。
5. 成功项提供“查看衣物”“打开预览”“进入工位”；使用现有资产详情与配置入口。

**产物**：导入子页面、任务 API、持久进度与结果入口。

**拟涉及模块**：新导入页面与组件、资产页面入口、目录查询／任务服务及 API。

**完成标准**：同一试导入清单从 UI 完成计划预览、启动、进度查看和结果跳转；页面刷新后能找到任务。界面保持折叠，不把每个样本的编辑器同时展开。

## 阶段 4：全量索引与选定批次转换

**输入**：已取得的完整数据目录和阶段 3 可用页面。

**操作步骤**：

1. 扫描全部本地样本并保存可查询索引；报告覆盖范围与缺失项，不把部分下载标成全量。
2. 支持服务端类别、来源、设计属性筛选和分页。人体／材料变体按可靠设计关系折叠。
3. 对用户选定的类别或清单分批转换；使用任务记录续接未完成项，已完成且版本一致的产物可复用。
4. 将成功项接入现有衣物库与批量运行入口；新增连衣裙、连体服等类别映射，保留不能映射的原始类别。
5. 根据真实样本测量索引查询、预览加载、单件转换和运行耗时，再决定缩略图缓存、并发度及是否需要降低网格分辨率。

**产物**：全量扫描报告、分页索引、批次转换任务与可使用的衣物资产。

**拟涉及模块**：目录索引存储、分页 API、衣物图库／选择器、转换队列、类别映射及批量入口。索引存储是否新建表或采用其他方式在实施范围中确定；本次不做数据库迁移。

**完成标准**：已下载样本全部可查；可选定批次转换和续接，正常重复导入不会重复注册同一转换版本；图库实际分页，不再受现有 250 件请求限制。

## 阶段 5：原始设计参数再生成

**输入**：已保留的设计参数、人体测量、生成程序版本与转换链。

**操作步骤**：先选一个类别和少量明确参数，调用匹配的 GarmentCode 程序重新生成，接回阶段 2 的转换与保存流程。新资产引用源设计／样本；原样本不变。

**产物**：按类别开放的编辑控件、重新生成结果与来源引用。

**拟涉及模块**：ClothForge 上游生成适配、Studio 类别参数配置与编辑器。

**完成标准**：至少一个类别的参数改动确实改变版片和网格，预览与保存一致，并完成一个代表样本的正常运行。其他类别没有验证前不显示为可调参。

## 导入问题与处理原则

| 问题 | 影响 | 处理与确认方式 |
| --- | --- | --- |
| 初始穿着形状被当作无应力形状 | 拉伸与弯曲响应失真 | 单独读取版片静止信息；缺失时明确需要重建，保留可浏览状态 |
| 单位／坐标不一致 | 尺度、重力方向或工位位置不正确 | 明确来源约定与转换变换，查看代表样本尺寸与方向 |
| 缝合、顶点、三角形对应错误 | 裂缝、错误连接或静止形状错位 | 追踪上游映射；转换报告记录实际来源与方法 |
| UV 缺失或纹理尺度不同 | 贴图拉伸、方向或接缝异常 | 区分原生／生成 UV，预览检查，记录重复次数及转换方式 |
| 材料参数不对应 Newton | 相同数字产生不同运动 | 原值与本地配置分别保存；先使用已有合成预设跑通，不声称已匹配上游材料 |
| 版片较多、网格较密 | 加载／运行慢、资源开销大 | 按需转换与加载；实测后讨论分辨率调整，不直接删片或破坏缝合 |
| 多人体／材料版本重复展示 | 款式数量被夸大、难以选择 | 设计分组与样本变体分开；同时显示设计数和样本数 |
| 本地文件不全、导入中断 | 部分转换或注册失败 | 明确样本及阶段，记录成功项，续接未完成项 |
| 模型仍穿在人体形状上 | 不适合直接进行桌面任务 | 明确初始姿态；另接放置／落布初始化并正常运行确认 |
| 修改参数无法复现原始设计 | 再生成不一致 | 固定上游版本、人体与参数；不把网格缩放当版片再生成 |

必要的文件、尺寸与对应关系检查属于转换本身。验证采用固定试导入批次和正常使用流程，不新增大规模防御性测试或全参数组合矩阵。预览成功、Newton 短轨迹、工位配置跳转、实际机器人运行与录制分别记录。
