# Newton 布料仿真接入方案

版本：v1  
核对日期：2026-09-17  
所属计划：[第一年里程碑与待办清单](YEAR1_MILESTONES.md)

## 1. 目标与当前决策

将 Newton 列为布料仿真的重点候选后端，利用现有 Newton 项目，逐步接入 robot-data-studio 的资产、运行、轨迹、回放和 QA 流程。Genesis、Isaac 的现有场景与报告提供对照；主后端选择以共同基准和实物测量为依据。

本方案是用户提出的工程补充，并非原 PDF 指定的技术路线。M1—M4 时间沿用原计划；新增工程指标须在实验前确定，不能视作企业已经确认的验收承诺。

本次批准与完成的范围是两份计划文档。下述代码接入、参数拟合和 GPU 实验均为待办，尚未执行；文档完成不等于 Newton 已接入 Studio。

## 3. 接入路径与数据边界

采用独立 Newton worker，复用现有 Studio 的引擎适配、进程管理和资源锁。初期沿用已存在的环境做复现核验，记录精确版本；升级依赖作为单独变更评估，避免旧报告与新求解器实现混用。

建议依次完成：

1. 资产层：登记 Newton 材料、网格、夹具、场景配置和证据路径；分别标注候选、数值验证、交互验证、实物标定状态。
2. 基准层：接入悬垂、拉伸、滑动等材料试验，保存原始顶点轨迹、约束类型、评价器版本和失败原因。
3. 机器人层：接入 Franka 接触抓布、保持、搬运和释放，记录真实动作语义、机器人状态、相机与任务评价。
4. 平台层：通过独立会话完成采集、回放、QA 和适用格式的导出，再开放批量生成。

代码实施前需逐项核对的现有接口：

| 接口位置 | 后续所需行为 |
|---|---|
| backend/src/robot_data_studio/adapters/ | 新增 Newton 描述、参数验证和 worker 启动适配；暴露真实支持的控制模式与能力 |
| backend/src/robot_data_studio/workers/ | 独立进程加载 Newton，处理就绪、停止、失败、输出及资源释放 |
| backend/src/robot_data_studio/config.py | 明确 Newton 项目根目录、解释器和输出配置 |
| backend/src/robot_data_studio/models.py、routes/episodes.py、lib/engines.ts、lib/types.ts | 同步引擎标识和验证规则，避免只增加前端选项却没有可运行后端 |
| packages/robot-data-contracts/ | 复用场景、软件来源与评价结构；核对动作、相机和机器人字段是否满足实际数据语义 |

以上是接口落点，不是本次已完成的代码修改清单。具体实现需在接口核查后给出独立的文件变更范围。

受控布料顶点的动作不是 Franka 关节动作。材料探测数据应保留为明确标识的基准记录；只有具备对应机器人状态、动作、时序及所需相机信息的数据，才进入相应机器人 Episode 和训练导出路径。缺失模态要明确声明或阻止不兼容导出，不能补造状态或相机标定。

必须区分固定夹具、运动学驱动区域与自由接触夹持。它们可以分别服务于研究，但不能混为同一种抓取成功证据。刚柔耦合的方向与能力也须记录，不能从布料跟随机器人运动推断已实现双向受力反馈。

## 4. 参数规范与可调界面

| 参数层 | 记录内容 | 调节与验证原则 |
|---|---|---|
| 实物面料 | 样本编号、尺寸、质量/面密度、厚度、经纬方向、测量条件、拉伸/弯曲/摩擦响应 | 原始测量关联样本和单位；未知值保留未知，不能用合成预设代替实测 |
| 几何与边界 | 网格拓扑、分辨率、初始形状、固定点/驱动点、桌面与夹具 | 保存初始状态和约束；比较时控制几何与边界条件 |
| 后端参数 | 引擎、求解器、粒子质量、拉伸/面积/弯曲项、阻尼、接触与摩擦参数 | Newton XPBD、Newton VBD、Genesis、Isaac 分别维护映射与适用范围；不直接复制刚度数值 |
| 数值参数 | 时间步、子步、迭代数、碰撞厚度、自碰撞配置、容差 | 与材料属性分开记录；调整数值精度后重新验证性能与误差 |
| 界面与版本 | 参数单位、有效范围、默认值、来源、预设版本、运行配置摘要 | 参数变更生成新运行记录；界面展示候选/验证/标定状态 |

参数使用 SI 单位对外表达；导入内部采用厘米等尺度的代码时，明确转换长度、速度、重力以及质量相关量，并逐项核对力和刚度的量纲。不要只缩放展示网格。

现有 mass/stretch/bend scale 属于有效参数扰动，并不是已标定的面密度或材料弹性常数。参数面板的范围须通过实际配置和稳定性测试确定。各后端允许不同内部参数，但应面向相同的可测物理响应标定。

## 5. 首批场景与扩展顺序

下表均为待接入/待验收项。已有源代码或其他后端资产不代表 Newton 场景已经验收。

| 顺序 | 场景 | 主要用途 | 交互与验收重点 |
|---|---|---|---|
| P0 | 双点悬挂、单角拉伸、保持/抖动探测 | 检查形变响应、阻尼和重复性 | 明确固定/驱动顶点；保存应变和顶点运动；不计为自由抓取 |
| P0 | 布料在桌面滑动 | 接触与摩擦测试 | 记录运动方式、法向条件和滑移曲线，避免用强制位移验证自由滑动 |
| P1 | Franka 布角抓取—抬升—保持—释放 | 首个机器人布料基准 | 接触保持、滑移、抬升、松爪后的自然脱离；保留失败轨迹 |
| P2 纺织厂 | 送布、边缘对齐、台面铺平 | 对应工位子任务 | 送进误差、边缘误差、平整度、卡滞和释放 |
| P2 家居 | 毛巾/餐布铺放、简单折叠、桌沿悬垂 | 扩展可复用材料与任务资产 | 放置误差、折叠偏差、褶皱和碰撞 |
| P3 | 多点分离、复杂褶皱、双臂协作 | 对应后续研究方向 | 基础接触任务通过后再扩大任务复杂度 |

优先让一套材料、一个网格和一个接触任务完整贯通，再复用到现有 24 套配置。批量场景数量不是验收指标；应记录各配置在哪个后端通过了哪些测试。

## 6. 共同基准与验收关卡

跨后端比较须冻结几何、初始状态、夹具、动作、材料目标响应、评价器及种子集合，并记录时间步、碰撞模型和网格分辨率差异。共同随机种子只是配置索引，不保证不同后端产生相同随机状态；实际初始状态应显式保存。

| 关卡 | 要检查的内容 | 通过后允许进入 |
|---|---|---|
| G0 配置与数据 | 单位、参数范围、引擎/求解器版本、约束类型、动作维度、时间戳和来源记录完整；不兼容配置明确报错 | 小规模基准运行 |
| G1 数值与材料响应 | 有限值、应变、地面及自接触穿透、静置漂移、参数响应和同环境重复性；记录仿真耗时与资源占用 | 接触任务调试 |
| G2 交互 | 抬升、保持、滑移、释放均按预先固定的规则评价；固定夹持与自由接触分别评测 | 机器人数据采集 |
| G3 平台闭环 | Studio 运行记录关联原始轨迹、参数、录像/回放、QA 和失败原因；执行对应导出及消费检查 | 可追踪的小批量数据生产 |
| G4 实物一致性 | 使用未参与拟合的动作或状态，与测量比较形状、伸长、动态响应和摩擦；报告误差与适用范围 | 实物面料模型验收与扩展 |

工程首轮建议使用 3 个预先固定的种子/初始状态作冒烟验证；这不是统计可靠性证明，也不是 PDF 已约定的验收数量。正式测试样本数、误差门槛、保持时长和资源预算应在运行前确定并版本化。

历史 Task 05 的 5 cm 门槛只解释那次实验；新任务的指标须明确参考位置、抬升统计方式、保持时长、释放判定和允许误差。诊断接触后可以设计新版本实验，但不能放宽旧阈值后回写“旧实验通过”。

当前尚不能据现有报告认定 Newton 优于其他后端。主后端决策需要同时考虑物理误差、交互可靠性、性能、可维护性和标定成本。无法直接比较的场景应说明差异，而非给出混合总分。

## 8. 实施优先级与记录规则

- [ ] 核验现有解释器运行状态，锁定源码快照与依赖；形成 Newton XPBD/VBD 能力表。
- [ ] 定义材料、场景、基准记录与机器人 Episode 的边界和单位。

- [ ] 完成首个机器人布料任务的 Studio 数据闭环。
